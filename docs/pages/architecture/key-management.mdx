# Key Management Architecture

3-layer key abstraction for flexible wallet support.

## Overview

```
┌─────────────────────────────────────────────────────────┐
│ Layer 3: KeyProvider (Orchestration)                     │
│ └─ MnemonicKeyProvider                                  │
└─────────────────────────────────────────────────────────┘
                           ↓
┌─────────────────────────────────────────────────────────┐
│ Layer 2: Account                                         │
│ └─ EOAAccountImpl: secp256k1, Cosmos                    │
└─────────────────────────────────────────────────────────┘
                           ↓
┌─────────────────────────────────────────────────────────┐
│ Layer 1: Signer (Curve-Specific Primitives)              │
│ └─ Secp256k1Signer: Cosmos                              │
└─────────────────────────────────────────────────────────┘
```

## Layer 1: Signer

Cryptographic primitives for signing.

### Interface

```typescript
interface Signer {
  readonly curve: CurveType;
  getPublicKey(): Uint8Array;
  signHash(hash: Uint8Array): Promise<SignatureResult>;
}
```

### Implementations

| Signer | Curve | Source |
|--------|-------|--------|
| `Secp256k1Signer` | secp256k1 | Mnemonic, private key |

### Key Operations

```typescript
// Get public key
const pubKey = signer.getPublicKey();

// Sign a hash
const signature = await signer.signHash(messageHash);
```

## Layer 2: Account

Account type abstraction.

### Interface

```typescript
interface Account {
  readonly kind: AccountKind;
  getSigners(): Signer[];
  getAddress(ecosystem: EcosystemType, chainId: string): Promise<string>;
}
```

### Implementations

| Account | Kind | Signers | Ecosystems |
|---------|------|---------|------------|
| `EOAAccountImpl` | eoa | secp256k1 | Cosmos |

### Address Derivation

```typescript
// Cosmos address
const cosmosAddr = await account.getAddress("cosmos", "cosmoshub-4");
// "cosmos1abc..."
```

## Layer 3: KeyProvider

Orchestration and lifecycle management.

### Interface

```typescript
interface KeyProvider {
  readonly type: KeyProviderType;
  getSupportedEcosystems(): EcosystemType[];
  getAccount(): Account | undefined;
}
```

### Implementations

| Provider | Type | Ecosystems | Account Type |
|----------|------|------------|--------------|
| `MnemonicKeyProvider` | mnemonic | Cosmos | EOA |

## Curve → Account Constraints

| Signer Curve | Account Type | Ecosystems | Notes |
|--------------|--------------|------------|-------|
| secp256k1 | EOA | Cosmos | Standard |

## Factory Pattern

```typescript
import { createKeyProvider } from "@keplr-wallet/keplr-wallet-mcp/keys";

// From mnemonic
const provider = createKeyProvider({
  type: "mnemonic",
  mnemonic: "word1 word2 ...",
});

```

## Registry Pattern

KeyProviders support plug-and-play extension via the **Registry pattern**.

### KeyProviderRegistry

Register new KeyProvider types without modifying core code:

```typescript
import { keyProviderRegistry } from "@keplr-wallet/keplr-wallet-mcp/keys";
import { z } from "zod";

// Register a new provider type
keyProviderRegistry.register({
  type: "my-provider",
  displayName: "My Wallet",
  configSchema: z.object({
    type: z.literal("my-provider"),
    apiKey: z.string(),
  }),
  create: async (config) => new MyKeyProvider(config),
});

// Create a provider via registry
const provider = await keyProviderRegistry.createProvider({
  type: "my-provider",
  apiKey: "...",
});
```

### AdapterBridgeRegistry

Bridge pattern for KeyProvider-to-Adapter integration:

```typescript
import { adapterBridgeRegistry } from "@keplr-wallet/keplr-wallet-mcp/keys/adapter-bridge";

// Register a bridge (per ecosystem)
adapterBridgeRegistry.register({
  providerType: "my-provider",
  ecosystem: "cosmos",
  createClient: async (provider, adapter) => {
    const myProvider = provider as MyKeyProvider;
    return adapter.createClient(await myProvider.getMnemonic());
  },
});

// Adapter automatically uses the bridge
const client = await adapterBridgeRegistry.createClient(provider, cosmosAdapter);
```

**Benefits:**
- Add new KeyProviders without modifying core code
- `createKeyProvider()` automatically supports new types
- Adapter's `createClientWithProvider()` automatically supports new providers
- Type-safe config validation via Zod schema

## Usage Flow

### Get Address

```typescript
const provider = store.getKeyProvider();
const account = provider.getAccount();
const address = await account.getAddress("cosmos", "cosmoshub-4");
```

### Sign Transaction

```typescript
const account = provider.getAccount();
const signers = account.getSigners();
const signer = signers[0];
const signature = await signer.signHash(txHash);
```
