# Plugin Types API

Interfaces for building external plugins for Keplr Wallet MCP.

## Import

```typescript
import type {
  KeplrMcpPlugin,
  ExternalPluginContext,
  ExternalPluginFactory,
  KeplrMcpConfig,
  RpcConfig,
  ToolsetConfig,
} from "@keplr-wallet/keplr-wallet-mcp";

import { defineConfig } from "@keplr-wallet/keplr-wallet-mcp";
```

---

## KeplrMcpPlugin Interface

The main interface for external plugins.

```typescript
interface KeplrMcpPlugin {
  name: string;
  setup?(ctx: ExternalPluginContext): Promise<void> | void;
  registerTools?(server: McpServer, ctx: ExternalPluginContext): Promise<void> | void;
  teardown?(): Promise<void> | void;
}
```

### Properties

#### `name`

```typescript
name: string;
```

Unique identifier for the plugin. Used in logs and error messages.

### Lifecycle Methods

#### `setup` (Optional)

```typescript
setup?(ctx: ExternalPluginContext): Promise<void> | void;
```

Called once before `registerTools`. Use for:
- Registering KeyProviders in the registry
- Registering AdapterBridges
- Fetching configuration or remote data
- Storing shared data in `ctx.set()`

All plugins' `setup()` calls complete before any `registerTools()` begins.

#### `registerTools` (Optional)

```typescript
registerTools?(server: McpServer, ctx: ExternalPluginContext): Promise<void> | void;
```

Register MCP tools, resources, and prompts. Called after all `setup()` calls complete.

#### `teardown` (Optional)

```typescript
teardown?(): Promise<void> | void;
```

Called on server shutdown. Use for cleanup (connections, timers, etc.).

## ExternalPluginContext Interface

Context object passed to `setup()` and `registerTools()`.

```typescript
interface ExternalPluginContext {
  get<T>(key: string): T | undefined;
  set(key: string, value: unknown): void;
  logger: ExternalPluginLogger;
}
```

### Methods

#### `get<T>(key)`

```typescript
get<T>(key: string): T | undefined;
```

Retrieve a value from the shared plugin data store. Keys are global — use a namespace prefix (e.g., `"my-plugin.chainData"`).

#### `set(key, value)`

```typescript
set(key: string, value: unknown): void;
```

Store a value in the shared plugin data store. Available to all plugins via `get()`.

### `logger`

```typescript
interface ExternalPluginLogger {
  debug(msg: string): void;
  info(msg: string): void;
  warn(msg: string): void;
  error(msg: string): void;
}
```

Logs are prefixed with the plugin name: `[my-plugin] INFO: message`.

## ExternalPluginFactory Type

```typescript
type ExternalPluginFactory = (options?: Record<string, unknown>) => KeplrMcpPlugin | KeplrMcpPlugin[];
```

Factory functions can return a single plugin or an array (for preset bundles).

## KeplrMcpConfig Interface

Top-level configuration type used with `defineConfig()`.

```typescript
interface KeplrMcpConfig {
  plugins?: (string | KeplrMcpPlugin | ExternalPluginFactory)[];
  toolsets?: Partial<ToolsetConfig>;
  rpc?: RpcConfig;
}

interface ToolsetConfig {
  default: string[];
}

interface RpcConfig {
  apiKey?: string;
  overrides?: Record<string, string>;
}
```

---

## defineConfig Helper

```typescript
function defineConfig(config: KeplrMcpConfig): KeplrMcpConfig;
```

Identity function that provides TypeScript type inference and autocomplete in `keplr-mcp.config.ts`.

```typescript
import { defineConfig } from "@keplr-wallet/keplr-wallet-mcp";

export default defineConfig({
  plugins: [myPlugin()],
  toolsets: { default: ["cosmos-query"] },
});
```

## Example Plugin

```typescript
import type { KeplrMcpPlugin, ExternalPluginContext } from "@keplr-wallet/keplr-wallet-mcp";
import type { McpServer } from "@modelcontextprotocol/sdk/server/mcp.js";
import { z } from "zod";

interface MyPluginOptions {
  rpcUrl?: string;
  debug?: boolean;
}

export default function myPlugin(options: MyPluginOptions = {}): KeplrMcpPlugin {
  const rpcUrl = options.rpcUrl ?? "https://rpc.cosmos.network";

  return {
    name: "my-cosmos-plugin",

    async setup(ctx: ExternalPluginContext) {
      ctx.logger.info(`Connecting to ${rpcUrl}`);
      // Validate connection
      ctx.set("my-cosmos-plugin.rpcUrl", rpcUrl);
    },

    async registerTools(server: McpServer, ctx: ExternalPluginContext) {
      const url = ctx.get<string>("my-cosmos-plugin.rpcUrl");

      server.registerTool(
        "my-cosmos-query",
        {
          description: "Query my Cosmos chain",
          inputSchema: {
            chainId: z.string().describe("Chain ID"),
            query: z.string().describe("Query to execute"),
          },
          annotations: { readOnlyHint: true },
        },
        async ({ chainId, query }) => {
          // Use url to query the chain
          return {
            content: [{ type: "text", text: JSON.stringify({ chainId, query, url }) }],
          };
        },
      );
    },

    async teardown() {
      // Close connections
    },
  };
}
```

## Internal Plugin Types (Advanced)

For advanced use cases, the internal `KeplrPlugin` interface is also exported:

```typescript
import type { KeplrPlugin } from "@keplr-wallet/keplr-wallet-mcp/plugin-types";
```

Internal plugins have direct store access and richer lifecycle hooks (`onAccountChanged`, `onClientInitialized`, etc.). External plugins are automatically wrapped into this interface.

See [Plugin System Architecture](/architecture/plugin-system) for details.
