# SDK Overview

Build custom adapters, protocols, and extensions for Keplr Wallet MCP.

## Package Structure

```
packages/
├── server/           # Core MCP server + Cosmos
└── protocol-osmosis/ # Osmosis DEX protocol
```

## Extension Points

| Type | Purpose | Examples |
|------|---------|----------|
| **EcosystemAdapter** | Support new blockchain ecosystems | Solana, Aptos |
| **ProtocolPlugin** | DeFi protocol integrations | Osmosis |
| **KeyProvider** | New key management methods | Custom wallets |
| **KeplrPlugin** | Custom MCP tools | Domain-specific tools |

## Exports

Import from the server package:

```typescript
// Ecosystem interfaces
import { EcosystemAdapter, EcosystemClient } from "@keplr-wallet/keplr-wallet-mcp/ecosystem";

// Key management
import { KeyProvider, Signer, Account } from "@keplr-wallet/keplr-wallet-mcp/keys";

// Plugin types
import { KeplrPlugin } from "@keplr-wallet/keplr-wallet-mcp/plugin-types";
import { ProtocolPlugin } from "@keplr-wallet/keplr-wallet-mcp/protocol-types";

// Store and errors
import { store } from "@keplr-wallet/keplr-wallet-mcp/store";
import { classifyError } from "@keplr-wallet/keplr-wallet-mcp/errors";

// SDK utilities
import { Int, Dec, CoinPretty } from "@keplr-wallet/keplr-wallet-mcp/sdk";
```

## Development Workflow

### 1. Create Package

```bash
mkdir packages/adapter-solana
cd packages/adapter-solana
pnpm init
```

### 2. Implement Interface

```typescript
import { EcosystemAdapter } from "@keplr-wallet/keplr-wallet-mcp/ecosystem";

export class SolanaAdapter implements EcosystemAdapter {
  // Implementation
}

export default () => new SolanaAdapter();
```

### 3. Test

```bash
pnpm test packages/adapter-solana
```

### 4. Register

Add to `keplr-mcp.config.ts`:

```typescript
import { defineConfig } from "@keplr-wallet/keplr-wallet-mcp/config";
import solanaPlugin from "@keplr-wallet/adapter-solana";

export default defineConfig({
  plugins: [solanaPlugin()],
});
```

## Core Concepts

### 3-Layer Key Abstraction

```
Layer 3: KeyProvider  → Orchestration (Mnemonic)
Layer 2: Account      → Account type (EOA)
Layer 1: Signer       → Cryptographic primitives (secp256k1)
```

### Confirmation Flow

All state-changing operations use two-step confirmation:

```
Tool call → Preview with token → Confirm with token → Execute
```

### Suggested Actions

Every response includes next step suggestions:

```typescript
{
  result: { ... },
  suggestedActions: [
    { tool: "next-tool", reason: "Why this action", priority: 1 }
  ]
}
```
